## Reviewer findings — 2026-11-20

- **MINOR V2-1 — Viewer-local timezone is not supplied to the clock model** (`plan.md:119`, `tasks.md:86-92`, `tasks.md:269`; CHK001, CHK016). The domain API deliberately treats a missing timezone as UTC, but the planned component flow calls `getTodayWidgetModel(now)` without a timezone. No task assigns browser IANA timezone discovery and forwarding. Implemented literally, this displays UTC to Manila users and fails the specified 1930h PHT E2E assertion. Specify browser timezone discovery on mount and pass that timezone to the date, ISO-week calendar-date, and clock model; retain UTC fallback only when discovery/validation fails. Add a component/E2E test proving the browser zone is forwarded, including a timezone where local date differs from UTC.
