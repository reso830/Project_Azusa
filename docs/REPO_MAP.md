# Repository map

Azusa 0.3.0 includes F001 foundations, F002 organization and cadence, and F003 work categories and allocation. Start here, then read the current feature's task slice. F004–F019 entries identify future ownership.

## Entry points and boundaries

| Location                                                                      | Responsibility and starting points                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`src/app/`](../src/app/)                                                     | Next.js routes and HTTP adapters. `layout.tsx` imports fonts and mounts `AppShell`; `globals.css` owns design tokens. Nine page routes load server health and render placeholders. `api/health/route.ts` and `api/health/check/route.ts` adapt service results to HTTP.                    |
| [`src/ui/shell/`](../src/ui/shell/)                                           | Presentation and interaction. Start at `AppShell.tsx`, `FloatingHeader.tsx`, `nav-config.ts`, and `shell.module.css`. `TodayWidget.tsx` supplies browser timezone to the pure calendar model. `page-health.ts` loads initial server health. Card/alert components present service results. |
| [`src/ui/icons/`](../src/ui/icons/)                                           | `kumiko-icons.ts` contains supplied paths; `KumikoIcon.tsx` renders size/color variants.                                                                                                                                                                                                   |
| [`src/domain/`](../src/domain/)                                               | Pure calendar rules (`calendar/iso-week.ts`), actor resolution (`audit/actor.ts`), and Zod contracts (`health/schemas.ts`). Keep React, Next.js, and database access out of domain calculations.                                                                                           |
| [`src/application/`](../src/application/)                                     | Use-case orchestration. `health/health-service.ts` validates records, reads health, writes diagnostics atomically, and preserves cached database/lock errors. Business invariants belong here/domain, not solely in UI controls.                                                           |
| [`src/persistence/`](../src/persistence/)                                     | `client.ts` owns the per-process context/startup; `lock.ts` owns shared canonical path identity and directory access; `backup.ts` owns snapshots, restore, recovery, pruning; `rename-directory.ts` handles bounded Windows rename contention.                                                                                |
| [`src/persistence/schema/`](../src/persistence/schema/)                       | `common.ts` provides audit columns; `app-metadata.ts` is F001's only application table; `index.ts` exports the schema.                                                                                                                                                                     |
| [`src/persistence/migrations/`](../src/persistence/migrations/)               | SQL, Drizzle journal, and generation snapshots belong together. `migrate.ts` runs migrations/seeding under caller-owned locking; it does not make the backup decision.                                                                                                                     |
| [`scripts/db/`](../scripts/db/)                                               | npm CLI adapters for migration, backup, restore; JSON output and nonzero failure exits.                                                                                                                                                                                                    |
| [`scripts/test/`](../scripts/test/)                                           | Browser bootstrap resets isolated storage, seeds it, and starts Next on port 3100. `acquire-playwright-lock.ts` adds test-only stale-lock retry; production acquisition remains fail-fast.                                                                                                 |
| [`tests/unit/`](../tests/unit/)                                               | Rules/contracts, icons, error/lock regressions, and `docs-completeness.test.ts`.                                                                                                                                                                                                           |
| [`tests/integration/`](../tests/integration/)                                 | Real PGlite restart, upgrade, backup, lock-loss, and promotion scenarios. Reuse `tests/support/backup-fixture.ts` where appropriate.                                                                                                                                                       |
| `tests/e2e/`, `tests/visual/`, `tests/support/`                               | Browser acceptance/accessibility, shell fidelity, and shared non-spec helpers. Never import helpers from another `.spec.ts` file.                                                                                                                                                          |
| [`docs/`](../docs/)                                                           | Roadmap, feature briefs, handoff archives, architecture, operations. [Index](../README.md) links the current artifacts.                                                                                                                                                                    |
| [`specs/001-application-foundations/`](../specs/001-application-foundations/) | F001 specification, plan, tasks/verification, contracts, research, quickstart.                                                                                                                                                                                                             |
| `.specify/`, `scripts/prompts/`                                               | Constitution/templates and per-step workflow instructions.                                                                                                                                                                                                                                 |
| [`.github/workflows/`](../.github/workflows/)                                 | `ci.yml` runs on pushes to `main` and every PR commit: lint, format, typecheck, Vitest, build, then Playwright e2e and visual sequentially (shared port 3100).                                                                                                                              |

Request flow: `app adapter → application service → domain validation + persistence → UI/HTTP response`. Client components never open database files. Server startup and `db:migrate` share backup/recovery orchestration through `getDbContext()`; the migration runner assumes its caller owns the lock.

| F019 ART board                                                                 | Extend planning/dependency read models and presentation; preserve owning Team rows and common ART iteration identities.                                           |
| Shell or route badge                                                           | `nav-config.ts` → owning `src/app/*/page.tsx` → shell components/CSS → visual/E2E tests. Replace placeholders only in the owning feature.                         |
| Database lifecycle/recovery                                                    | `client.ts`, `backup.ts`, `lock.ts` → CLI adapters → integration tests → [runbook](operations/database-and-recovery.md).                                          |

For persisted changes, update schema, generate/review explicit migration SQL and metadata, test fresh/existing databases, and update the [data dictionary](architecture/data-dictionary.md). Maintain this map when paths or responsibilities change.

## Verification cost and isolation

Use focused tests while editing, then the required broader gates when ready. Browser suites share port 3100/storage and run sequentially. Test-server startup allows 180 seconds for database seeding and cold compilation; the two nine-route workflows allow 90 seconds each. These test-only budgets do not change production lock timing. Keep `.next-playwright` separate from `.next`; never run a default dev server and production build against the same output directory. Vitest defaults are temporary; Playwright uses `.azusa/test-playwright/`. See [architecture](architecture/overview.md) and the [runbook](operations/database-and-recovery.md) for runtime and storage tradeoffs.
